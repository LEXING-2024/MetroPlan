# 全方式出行热力图

状态：已接入 M2 活动链，且是默认模式。**没有地铁时，步行 / 电动车 / 公交 / 小汽车的背景出行也会进入热力图**；旧模型只用于旧存档兼容。

![没有地铁时的背景人流热力](../preview/heat-background.png)

## 之前为什么看不到

`buildHeatFrame()` 只统计：

- `WalkToStation`
- `Waiting`
- `Riding`
- `WalkToDest`

M2 的背景方式状态是 `InBackground`，被排除在热力之外。因此：

- 没建地铁时，活动链出行全部在背景方式里；
- 热力图几乎是空的；
- 只有建站后，步行接驳 + 候车 + 列车才有热力。

## 现在怎么统计

`AgentFields` 新增：

```text
bgFromX / bgFromY   背景出行起点
tripDestX / tripDestY  背景出行终点（已有）
bgTotal             背景出行总分钟
bgMode              0 步行 / 1 电动车 / 2 公交 / 3 小汽车
```

`buildHeatFrame()` 对 `InBackground`：

```text
f = 1 - walkLeft / bgTotal
x = fromX + (toX - fromX) × f
y = fromY + (toY - fromY) × f
```

- 位置按时间线性插值；
- 身后拖 3 段尾迹，形成走廊；
- 步行/电动车权重 1.0；
- 公交/小汽车权重 0.8；
- 全部计入 `activePeople`，并单独统计 `backgroundPeople`。

## 覆盖范围

- **所有正在移动的 agent**：地铁方式 + 背景方式；
- 在家、在岗、静止的人不计；
- 没有地铁时，活动链中所有出行都会进入热力；
- 热力是**人流密度**，不是每个人的精确轨迹/路线。

## 低值增强与图例

旧归一化按峰值线性压缩，峰值 1,000 人时只有十几个人的地方几乎看不见。

现在使用对数压缩：

```text
values = pow(log1p(v) / log1p(peak), 0.7)
```

- 10 人的地方保留可见的浅色；
- 1,000 人的走廊仍然到最高色；
- 不再是“只有几个红点”；
- 左下角新增人流图例：少 → 多，颜色与热力层一致；
- 空间核从 0.9/1.1 收窄到 0.5–0.8，桥头/道路走廊不再糊成很宽的一条带；
- 低于 0.18 的噪声归零，保留十几人的浅色热力。
- 图例随“实时热力”图层自动显示/隐藏。

M1 默认模型（10,136 人、19,065 段 trip）：

## 怎么开启

默认新游戏就是 M2 活动链，不需要参数：没有地铁时，背景出行会直接进入热力图。  
M3/M4 默认开启；`?m3=0&m4=0` 关闭步行图；`?commuter=1` 切纯通勤实验。

## 限制

- 背景路径默认按路网折线插值；尚未完成路网时暂时直线，后台队列会在几秒内补齐；找不到主连通分量时回退直线；
- 公交/小汽车没有道路容量、班次和拥堵；
- 热力不区分方式颜色，只显示总人流；
- 旧存档兼容模式没有背景方式；
- 自行车/电动车只作为背景速度，没有单独非机动车道。

## 为什么以前还有很多直线

热力图里“在移动的人”有三类位置来源，之前都在用直线插值：

1. `WalkToStation` / `WalkToDest`：直接用起点到车站、车站到终点的直线插值；
2. `Riding`：列车位置用相邻站直线插值，没有跟随线路曲线；
3. `InBackground`：有路径时沿路径走，但路径还没算好、或 OD 在步行图外时，回退到两点直线。

所以即使 agent 的真实路径是沿路的，热力尾迹仍然会画成一条条直线。

## 现在的处理

- M3 步行接驳直接复用已经算出的 `walk1 / walk2` 路径；M4 用粗网格路径补一条供热力使用的轨迹；
- 列车热力使用与线路绘制相同的贝塞尔曲线 + `smoothTravel()`；
- 背景步行 / 电动车在 48px 粗网格上预计算所有格子的最短路前驱表，单次查询约 0.01ms，不再排队等完整步行图 A*；
- 仍然解析不出路径的 agent，只画一个当前位置点，**不再拖出假直线尾迹**；
- 背景队列积压时每 tick 处理上限提高到 128，6ms 预算，队列会很快降到 0。

剩余直线只可能来自：最长 160–240px 的“家门口 → 最近步行节点”连接段，以及完全在步行图覆盖范围外的点。这些不再被画成整条 OD 直线。
